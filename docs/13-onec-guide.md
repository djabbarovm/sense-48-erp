# Подключение 1С:Бухгалтерии к Finance OS (практическое руководство)

Принцип разделения (CLAUDE.md): **система — источник истины операций, 1С — регламентированный учёт.**
Finance OS не заменяет 1С и не ведёт план счетов — она готовит данные так, чтобы бухгалтер
проводил их в 1С за минуты, а не собирал по Telegram.

## 0. Как получить доступ к 1С (что попросить)

У бухгалтера/обслуживающей фирмы попросите (в порядке предпочтения):
1. **Пользователя в базе c правами «Только просмотр»** + тонкий клиент 1С (или публикацию базы на веб-сервере — тогда достаточно браузера). Этого хватает, чтобы сверять остатки и проводки.
2. **Копию базы (выгрузку .dt)** — для изучения структуры и настройки обмена без риска для рабочей базы.
3. Ответы на три вопроса: конфигурация и релиз («1С:Бухгалтерия 8 для Узбекистана», ред. ?), ведётся ли Клиент-Банк через файловый обмен, каким модулем отправляются ЭСФ (Didox / встроенный).

ЭЦП, пароли базы и коды никому не передавать — они остаются у бухгалтера (BR-072/док. §9).

## 1. Три потока обмена

### 1.1 Платёжки → Клиент-Банк / 1С (файл `1CClientBankExchange`)
На карточке утверждённого реестра кнопка **«Выгрузка 1С (платёжки)»** формирует `BATCH-…-1c.txt`
в стандарте «Обмен c системами Клиент банка» (версия 1.02, кодировка Windows-1251, в поле БИК — МФО).
Файл принимают и банковские Клиент-Банки («Импорт из 1С»), и сама 1С (Банк → Загрузка/выгрузка платёжных поручений).
Итог: платёжки не набиваются руками ни в банке, ни в 1С.

### 1.2 Проводки месяца → 1С (CSV `postings`)
Экран «1С» → «Экспорт проводок за период»: все оплаченные платежи месяца одной таблицей
`payment_request_number; paid_at; vendor…; amount; vat; account_code; vat_account_code; cost_center; category; …`.
`account_code` берётся из маппинга категорий (админка, стартовые значения — НСБУ-21: 1010 материалы,
2910 товары, 9410 расходы по реализации, 9420 административные, 0820 приобретение ОС, НДС — 4410).
В 1С файл загружается типовой обработкой **«Загрузка данных из табличного документа»** либо
внешней обработкой (одноразово заказывается 1С-нику; структура файла стабильна).

Типовые корреспонденции (справочно, решает бухгалтер):
- Оплата поставщику: Дт 6010 (или 4310 при авансе) — Кт 5110.
- Поступление ТМЦ/услуг: Дт 1010/2910/9410/9420 (+Дт 4410 НДС) — Кт 6010.
- Зачёт аванса: Дт 6010 — Кт 4310. Подотчёт: 4220/4230. Зарплата: 6710. Налоги: 6410.

### 1.3 Подтверждение проводок ← 1С (CSV `posted`)
После проведения бухгалтер выгружает подтверждение
(`payment_request_number;posted_at;onec_document_ref`) — импорт на экране «1С» закрывает платежи
(RECONCILED → CLOSED) и сохраняет ссылку на документ 1С. Круг замкнут: в Finance OS видно,
что дошло до регламентированного учёта.

## 2. ЭСФ / Didox

Didox уже интегрирован c 1С для Узбекистана (модули «1С-ЭСФ»/Didox). Finance OS живёт от
**реестра СФ** (Didox → Excel-выгрузка реестра → импорт на экране «Счета и СФ»), поэтому
дублирования с 1С нет: счёт-фактуры попадают и в 1С (через модуль ЭСФ), и в Finance OS (реестр),
сверяясь по номерам. Когда появится API-доступ Didox — реестр будет забираться автоматически
(адаптер уже изолирован интерфейсом).

## 3. Порядок месяца (чеклист бухгалтера)

1. Ежедневно: платёжки — из Finance OS файлом в Клиент-Банк (1.1); выписка — из Клиент-Банка в Finance OS (экран «Банк и сверка»).
2. До 5-го числа: экспорт проводок за месяц (1.2) → загрузка в 1С → проведение.
3. После проведения: выгрузка posted.csv → импорт в Finance OS (1.3).
4. Сверка: AP aging Finance OS ↔ ОСВ по 6010/4310 в 1С; расхождения — через экран «Сверка с поставщиком».
